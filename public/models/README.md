# 蚕房 3D 模型接入约定（真实建模替换程序化模型）

当前大屏里的蚕房是**程序化生成**的（Three.js 基础几何体拼装，见 `src/three/houseStructure.ts`）。
把真实建模文件放到本目录，即可替换成真模型，其余全部保留：
4 蚕房 2D 总览、点击进入居中 3D、告警光柱定位、蚕架透视/隐藏、相机档位、整机升降与传送动画。

---

## 一、需要给我什么文件

### 首选：**一个 `.glb` 文件**
```
public/models/canfang.glb        ← 文件名固定用这个
```
GLB = glTF 2.0 二进制单文件，**贴图可以全部打包在里面**，不会丢资源，Three.js 支持最好。

### 其他可接受格式
| 格式 | 说明 |
| --- | --- |
| ⭐ **GLB** | 首选，单文件带贴图 |
| ✅ `.gltf` + `.bin` + `textures/` | 打包成 **zip** 给我也行，我会解压并保持相对路径 |
| ✅ **FBX** | 3ds Max / Maya / Blender 常用，贴图要一起给（建议先用 Blender 转 GLB） |
| ✅ **OBJ + MTL + 贴图** | SketchUp / CAD 静态模型常用，无动画、文件偏大 |
| ✅ **DAE (Collada)** | SketchUp 常用导出格式 |
| ⚠️ STL | 只有三角面、无材质（灰模），需要我补材质 |
| ➕ IFC | 要额外接 `web-ifc`，提前告知 |
| ❌ STEP / IGES / SLDPRT / DWG | 浏览器不能直接用，须先用 Blender / FreeCAD 转 GLB |

**zip 也可以**：如果模型是多文件（glTF + bin + 贴图 / FBX + 贴图），直接给 zip，我来解压落位。

## 二、尺寸与坐标（很重要，决定能不能一次对齐）

| 项 | 要求 |
| --- | --- |
| 坐标轴 | **Y 轴朝上**（3ds Max 默认 Z-up，导出时勾选 Y-up，或告诉我，我加旋转补偿） |
| 原点 | 放在**蚕房地面中心**（便于直接对齐园区坐标） |
| 单位 | 按**米**建模 |
| 当前蚕房尺寸 | **长 16m（X）× 深 15m（Z）× 高 5.5m（Y）** |
| 若尺寸不同 | 告诉我真实长宽高，我用代码整体缩放对齐即可 |

## 三、部件命名约定（决定"真模型能不能动起来"）

**把下面这些部件做成各自独立的 mesh，并按名字命名**（大小写不敏感，可加后缀编号）。
有这些名字，我就能把现有的动画与告警逻辑直接绑上去；否则只能整体显示，需要我按几何位置重新绑（更费时）。

### 1. 建筑
| 节点名 | 说明 | 现有表现 |
| --- | --- | --- |
| `room_frame` | 立柱 / 顶梁框架 | 常态 |
| `room_glass` | 幕墙 | 半透明，可透视看内部 |

### 2. 蚕架与蚕盘
| 节点名 | 说明 | 现有表现 |
| --- | --- | --- |
| `rack_a` / `rack_b` | 前后两排蚕架（或用 `rack_` 前缀整组） | 可一键"隐藏蚕架"，也支持半透明透视 |
| `tray_static_*` | 货架上静止的蚕盘 | 常态 |
| `tray_moving_*` | 需要运动的蚕盘（可留空，我用代码生成） | 随传送带运行 |

### 3. 码垛机（本轮重点：整机升降 + 左右伸缩臂 + 双槽平台）
| 节点名 | 说明 | 现有动画 |
| --- | --- | --- |
| `palletizer_body` | 长方形整机车身 | **整机上下升降**（升到目标蚕架层 / 降到传送带高度） |
| `palletizer_slot_a` / `palletizer_slot_b` | 车顶两个放盘槽位 | 两盘周转 |
| `palletizer_arm_left` | 左侧伸缩机械臂（对蚕架 A） | 三级伸缩：伸入蚕架取放 |
| `palletizer_arm_right` | 右侧伸缩机械臂（对蚕架 B / 传送带） | 同上 |
| `palletizer_fork_left` / `_right` | 托叉（从蚕盘下方插入） | 平进平出 + 0.16m 小抬起 |
| `palletizer_rail` | 地面轨道 | 静止 |

### 4. 传送系统
| 节点名 | 说明 | 现有动画 |
| --- | --- | --- |
| `conveyor_green` | 绿色长传送带（左→右） | 蝉盘沿带面运行 |
| `conveyor_blue_left` | 左蓝色传送带（向下） | 循环输送 |
| `conveyor_blue_right` | 右蓝色传送带（向上） | 循环输送 |
| `hopper_bin` | 投叶漏斗料仓 | 静止 |
| `hopper_gate` | 漏斗闸门 | **有蚕盘经过时开闸投叶** |

### 5. 抓取机（现为待机展示）
| 节点名 | 说明 |
| --- | --- |
| `grabber_portal_1` / `grabber_portal_2` | 两台跨带门架 |
| `grabber_beam_1` / `_2` | 门架横杠 |
| `gripper_1` / `gripper_2` | 长方形夹爪（待机收在横杠下方） |

### 6. 环境设备与监测节点（决定告警光柱打在哪）
| 节点名 | 对应大屏节点 | 告警表现 |
| --- | --- | --- |
| `sensor_01` | 温湿度传感器 | 温度/湿度预警时光柱 + 标红呼吸 |
| `ac_left` / `ac_right` | 空调机组 | 同上 |
| `air_supply_1` / `air_supply_2` | 出气机组 | 常态 |
| `air_exhaust_1` / `air_exhaust_2` | 排气机组 | 常态 |
| `rack_monitor_01` | 蚕箔架监测 | 病蚕预警时光柱定位 |

> 只给一个整体模型也能用（整体旋转/缩放/透视），但**升降、传送、投叶这些动画需要独立部件**才能做；
> 可以后续再把部件拆出来补命名。

## 五、给我文件之后我会做的事

1. 在 `public/models/` 放好模型，加载器加 `GLTFLoader`（+ Draco 解码器，如需要）
2. 把 `houseStructure.ts` 里的程序化构建替换为"**加载真模型 + 按节点名挂动画与告警**"
3. 保留：2D 总览、点击居中展示、告警光柱/引线标注、蚕架透视与隐藏、相机档位、整机升降与传送循环
4. **存在即用、不存在自动回退**：模型缺失时继续用程序化模型，演示现场不会白屏
5. 若尺寸/朝向不一致：我按你给的真实尺寸做整体缩放与旋转对齐
