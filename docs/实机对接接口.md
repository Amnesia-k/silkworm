## 1. 设计约定（改动前请先读）

1. **同一份页面代码**：页面只调用 `utils/data.js` 的 getter（`getStatusSummary / getSeries / getAlarms / getDevices / getMachines / getConfigView / getDayReport`）。实机数据由网关写进 `data.js` 的**覆盖层**，getter 命中即返回、未命中的字段沿用模拟值，**页面零改动**。
2. **默认不联网**：默认 `mode: 'sim'`，`gateway.start()` 直接返回 `false`，不发任何请求（`tools/check-gateway.js` 断言「0 次网络请求」）。只有切到 `mode: 'live'` 且填了 `baseUrl` 才会走网络。
3. **可插拔传输**：HTTP 走 `setTransport(fn)` 注入，默认实现用 `wx.request` / `uni.request`；MQTT、硬件网关盒、私有协议只需实现同一个 `{url, method, data, header, timeoutMs} → Promise<{status, body, raw, ms}>`。
4. **写路径永不静默回落**：实机模式下 `command / pushConfig / palletJob` 失败只会返回错误码，**不会**落到本地模拟引擎去「假装成功」（安全要求：控制指令不能凭空生效）。
5. **单位与时间**：所有时间戳为 **epoch 毫秒**；温度 ℃、湿度 %RH、时长秒；`agg=min` 为分钟点，`agg=hour` 为小时聚合点。
6. **只读失败不污染**：任何只读接口失败都**不写覆盖层**（页面继续显示上一份数据/模拟值），错误只进 `gateway.getState()` 与请求日志。

## 3. 通用报文约定

**请求头**：`Authorization: Bearer <token>`（`token` 为空则不带）；命令类请求额外带 `X-Idempotency-Key: <clientId>`。

**响应信封**（两种都接受）：

```json
{ "ok": true,  "data": { ... } }                       // 推荐
{ "ok": false, "code": "E_LOCK", "message": "设备锁定中" }
```

裸 JSON（无信封）也接受；`body` 为空 → `ENVELOPE`；`ok:false` → 透传 `code/message`。

**统一错误码**（客户端侧）：

| code | 含义 | 是否重试 |
| --- | --- | --- |
| `NOT_LIVE` / `NO_CONFIG` / `NO_BARN` | 未切实机 / 未填地址 / 未选蚕房 | — |
| `TIMEOUT` / `NETWORK` / `NO_API` | 超时 / 网络失败 / 无 request API | 重试 |
| `HTTP_4xx` | 请求被拒（含权限、参数） | 不重试 |
| `HTTP_5xx` | 服务端错误 | 重试 |
| `ENVELOPE` | 报文为空或不可解析 | 不重试 |
| `REJECTED` 及后端自定义码（如 `E_LOCK`） | 后端业务拒绝，原样透传给页面 | 不重试 |

重试次数 = `1 + retry`（`retry=2` → 最多 3 次请求）。

## 4. 只读接口（后端必须实现）

基础路径统一为 `{baseUrl}/barns/{barn}`，`barn` 形如 `barn01`。

### 4.1 `GET /health` → 连通性测试

```json
{ "ok": true, "data": { "version": "1.0.0", "uptimeSec": 12345 } }
```

### 4.2 `GET /barns/{barn}/status` → 工况快照（看板 / 控制页 / 我的）

```json
{ "ok": true, "data": {
  "temp": 25.6, "humi": 68.4, "dewp": 19.1,
  "online": true, "sensorOk": true, "mode": "auto",
  "wifi": 3, "serverState": "online",
  "target": { "tMin": 24, "tMax": 26, "hMin": 65, "hMax": 75 },
  "outOfRange": { "temp": false, "humi": true },
  "devices": [ { "id": "heat01", "on": true } ]
} }
```

`mode` ∈ `auto|manual|maint`；未返回的字段（如 `modeName/tempText/wifiText/lastReportText`）自动沿用模拟侧计算的展示值（`merge` 语义）。

### 4.3 `GET /barns/{barn}/series?from=<ms>&to=<ms>&agg=min`

分钟点数组（也可包 `{ points: [...] }`）：

```json
{ "ok": true, "data": { "points": [
  { "ts": 1791696000000, "temp": 25.4, "humi": 68.1, "outSec": 0 }
] } }
```

- 字段别名均接受：`ts|time|timestamp|at|collectAt|sampleAt`、`temp|temperature|tempC|tempVal`、`humi|humidity|rh|humiPct|humidityPct`、`outSec|outSeconds|out_of_range_sec`。
- `tMin/tMax/hMin/hMax/outTemp/outHumi` 缺省时由客户端用 `data.getTarget(barn)` 的当时目标区间补齐并计算越限。
- **曲线页按此接口取数**，`from/to` 是当前窗口（缩放手势会改变窗口，页面会带新窗口再请求一次）。

### 4.4 `GET /barns/{barn}/series?from&to&agg=hour` 或 `GET /barns/{barn}/hourly?from&to` → 小时聚合（日报 / 长跨度曲线）

```json
{ "ok": true, "data": [ { "ts": 1791692400000, "tempAvg": 25.3, "tempMax": 26.1, "tempMin": 24.2,
  "humiAvg": 69.0, "humiMax": 73.0, "humiMin": 65.0, "outSec": 120, "samples": 60 } ] }
```

### 4.5 `GET /barns/{barn}/alarms?status=active|acked|all` → 告警列表

```json
{ "ok": true, "data": [
  { "id": "AL-0007", "code": "T_HIGH", "level": "warn", "deviceId": "fan01",
    "ts": 1791696000000, "value": 26.8, "text": "温度 26.8 ℃ 高于上限 26 ℃",
    "advice": "开启排气扇", "acked": false, "active": true }
] }
```

`data` 也可为 `{ list: [...], stats: {...} }`。客户端只透传数组，`levelName/levelColor/timeText/agoText` 等展示字段由本地 `decorateAlarm` 补。

### 4.6 `GET /barns/{barn}/devices` → 设备台账（控制页 / 我的）

```json
{ "ok": true, "data": [
  { "id": "heat01", "name": "加热片", "kind": "heat", "on": true, "online": true,
    "locked": false, "runtimeMin": 128, "switchesToday": 6, "faultCode": "" }
] }
```

`kind` ∈ `heat|fan|mist|...`（与 `utils/spec.js` 的设备种子一致）。其余展示字段（`kindName/spec/stateText/runtimeText/canSwitch/cooldownLeft`）未返回时沿用本地计算。

### 4.7 `GET /barns/{barn}/machines` → 机械化设备（空调 / 排气扇 / 投叶漏斗 / 抓取机 / 码垛机）

```json
{ "ok": true, "data": [
  { "id": "ac01", "name": "空调", "kind": "hvac", "on": true, "online": true, "locked": false,
    "runtimeMin": 320, "switchesToday": 4, "cycles": 12, "outCount": 0,
    "params": [ { "key": "T_set", "value": 25.0 } ] }
] }
```

`params[]` 只需回 `key` + `value`（可带 `text`）；`label/unit/min/max/step/presetText/ok/dir/outText` 由本地 `MACHINE_SEEDS` 规格补齐。

### 4.8 `GET /barns/{barn}/config` → 目标区间与策略（配置页 / 我的）

```json
{ "ok": true, "data": {
  "ver": "v1.01.0", "by": "张工", "note": "升温 0.5 ℃",
  "range": { "tMin": 24, "tMax": 26, "hMin": 65, "hMax": 75, "tol": 0.4, "tSet": 25, "hSet": 70 }
} }
```

### 4.9 `GET /barns/{barn}/report?date=<ms>&agg=hour` → 日报

```json
{ "ok": true, "data": {
  "date": 1791648000000, "samples": 1440,
  "tempAvg": 25.2, "tempMax": 26.4, "tempMin": 24.0,
  "humiAvg": 69.1, "humiMax": 74.0, "humiMin": 64.5,
  "outRate": 0.031, "alarmTotal": 3, "alarmCritical": 0, "alarmWarn": 2, "alarmInfo": 1,
  "switches": 18, "hours": [ { "ts": 1791692400000, "tempAvg": 25.3 } ]
} }
```

### 4.10 页面对接口速查

| 页面 | 用到的接口 |
| --- | --- |
| 看板 `pages/index` | `status` + `series(近 6 h, min)` |
| 曲线 `pages/history` | `series(min)`（缩放手势会按新窗口再取） |
| 告警 `pages/alerts`、告警详情 | `alarms?status=` |

## 5. 写入接口（控制指令）

> 实机模式下这些调用**不会**回落本地模拟；后端未实现时页面会拿到错误码并提示。

### 5.1 `POST /barns/{barn}/commands` —— 通用命令（设备开关 / 机械动作）

```json
{ "ok": true, "data": { "accepted": true, "cmdId": "C-1024", "at": 1791696000000 } }
```

请求体：

```json
{ "target": "device",            // device | machine
  "id": "heat01",                // 设备 / 机械 id
  "action": "on",                // on | off | startJob | cancelJob | ...
  "params": { "T_set": 25.5 },   // 可选
  "tokenId": "TK-2",             // 审批令牌（控制页申请后带）
  "note": "现场确认",             // 可选备注
  "clientId": "gw-barn01-1791696000000-1",   // 幂等键，同值在 X-Idempotency-Key
  "at": 1791696000000 }
```

### 5.2 `POST /barns/{barn}/config` —— 参数下发

```json
{ "ver": "v1.01.0", "by": "张工", "note": "升温 0.5 ℃",
  "range": { "tMin": 24, "tMax": 26, "hMin": 65, "hMax": 75, "tol": 0.4, "tSet": 25, "hSet": 70 },
  "clientId": "gw-barn01-…", "at": 1791696000000 }
```

### 5.3 `POST /barns/{barn}/tokens` —— 申请审批令牌

```json
{ "action": "manual", "ttlSec": 900, "reason": "现场维修" }
→ { "ok": true, "data": { "tokenId": "TK-3", "expireAt": 1791699600000 } }
```

### 5.4 `POST /barns/{barn}/alarms/{id}/ack` —— 确认告警

```json
{ "memo": "已开启排气扇", "at": 1791696000000 }
```

## 6. 实时推送（可选，推荐）

- 配置 `wsUrl` 后 `gateway.start()` 建连并发订阅报文；未配置则按 `pollMs` 轮询 `pullAll`（首轮 6 个只读接口并发）。
- 订阅报文：`{ "type": "subscribe", "barn": "barn01", "token": "…" }`
- 推送报文：

```json
{ "type": "status",  "barn": "barn01", "data": { "temp": 25.8 } }
{ "type": "series",  "barn": "barn01", "from": 1791692400000, "to": 1791696000000,
  "data": [ { "ts": 1791696000000, "temp": 25.8, "humi": 68.0 } ] }
{ "type": "alarm",   "barn": "barn01", "filter": { "status": "active" }, "data": [ /* 告警数组，全量替换 */ ] }
{ "type": "device",  "barn": "barn01", "data": [ /* 设备数组 */ ] }
{ "type": "machine", "barn": "barn01", "data": [ /* 机械数组 */ ] }
```

- 断线自动重连：`min(30 s, 2 s × 第几次)`，重连后重新发订阅报文。
- 写接口的受理结果（`cmdId`/`accepted`）也建议通过 `status`/`machine` 推送回传。

## 7. 逐页接入示例（3 行改造）

页面现在直接调本地引擎；切实机后建议改成「先请求、成功则用返回结果、并让本地引擎停写」。例如控制页：

```js
const gateway = require('../../utils/gateway.js')
// 原：engine.toggleDevice(barn, id, tokenId)
gateway.command(barn, { target: 'device', id: id, action: on ? 'off' : 'on', tokenId: token })
  .then((r) => wx.showToast({ title: r.ok ? '指令已受理' : (r.code + '：' + r.message), icon: 'none' }))
```

配置页：`gateway.pushConfig(barn, patch, note, ver)`；机械化页：`gateway.palletJob(barn, 'pallet01', { coords })`；
告警页：`gateway.ackAlarm(barn, alarmId, memo)`；令牌：`gateway.issueToken(barn, { action: 'manual' })`。

## 8. 后端实现顺序（建议）

1. `GET /health`（先打通链路，小程序「测试连接」即可变绿）。
2. `GET /status` + `GET /series?agg=min`（看板与曲线先动起来）。

## 10. 已知边界

- **覆盖层是内存态**：小程序重启后需重新同步（`start()` 会自动拉一轮）。
- 未提供字段一律沿用模拟值，可能出现「温度是实机的、湿度还是模拟的」的混合显示——联调时应逐字段核对后端是否返回。
- `sim → live` 切换会清空覆盖层；`live → sim` 会 `clearLive()` 并停止数据流。
- 曲线缩放手势按新窗口重新取数的场景，后端需支持任意 `from/to`（跨度 10 min ~ 24 h）。

## 11. 病蚕识别 / 人工裁定 / 夹取作业（已接真实后端）

这一层**不走** `gateway.js` 的覆盖层，而是独立客户端 `utils/clamp.js` 直接调用后端（契约见 `20_前端交付单（安卓App接口与传参）.md`）。

### 11.1 配置

| 项 | 值 |
| --- | --- |
| 存储键 | `silk_clamp_v1`（`clamp.CONFIG_KEY`） |
| 字段 | `baseUrl`（默认 `http://10.66.66.1/api`）、`token`（默认 `test`，服务端只校验非空）、`zone`（默认 `zone01`）、`barn`（留空＝跟随当前选中蚕房）、`pollMs`（5000~120000，默认 20000）、`timeoutMs`（默认 12000）、`confirmTimeoutMs`（30000~120000，默认 35000） |
| 页面入口 | **我的 → 后端接口**：改地址/令牌/区域、测试连接、立即同步、查看最近 5 条请求 |

### 11.2 用到的接口

```text
GET  {base}/barns/{barn}/diseased?status=pending|done|all&limit=1..500&zone=
POST {base}/barns/{barn}/diseased/{trayId}/confirm?zone=
GET  {base}/barns/{barn}/clamp/jobs?status=all|running|done&limit=1..500&zone=
GET  {base}/barns/{barn}/patrol/status        （可选，仅我的页展示，不下发）
```

- 信封：成功 `{"ok":true,"data":…,"total":n}`；失败 `{"ok":false,"error":{"code","message"}}`，`code` 原样保留供排查，界面显示 `clamp.ERROR_TEXT` 的中文。
- 重试：401 / 4xx 不重试；5xx / 网络异常 / 超时退避重试 1 次；`confirm` 默认不重试（避免重复下发机械），靠 `X-Idempotency-Key: clamp-<barn>-<trayId>-<ts>` 做幂等。
- 裁定 `yes` 会阻塞到阶段回执（最坏约 19 s），客户端超时 35 s。
- `placed === true` 才代表真的夹取放到位；按钮是否出现只看 `canConfirm`（字段缺失时按 `status=pending && level=info` 推导）。

### 11.3 轮询与页面接线

- 无推送，进入机械页后每 `pollMs` 拉一次（待裁定列表 + 作业列表），裁定成功后立即 `refreshAll()`。
- 定时器**只有一个**（`utils/clamp.js` 模块级），页面用 `clamp.startPolling(barn, fn)` 订阅、`clamp.stopPolling(fn)` 退订，没有订阅者时清掉定时器——遵守「页面不自起定时器」的约定。
- 看板/控制页只订阅计数（待裁定病蚕数），机械页订阅完整列表。

### 11.4 已删除的模拟部分（避免两套数据打架）

| 已删 | 位置 | 替代 |
| --- | --- | --- |
| `createDiseased(seed, now)` 本机生成病蚕 | `utils/data.js` | 后端 `GET …/diseased` |
| 病蚕记录初始数据（`barn.diseased`） | `utils/data.js` | 初始为 `[]`，由接口填充 |
| `engine.startPalletJob()` / `cancelPalletJob()` | `utils/engine.js` | 裁定 `yes` 后由**服务端**自动下发夹取 |
| 机械卡「码垛作业」进度块 + 坐标弹层 | `pages/machine` | 「夹取作业」列表（`clamp/jobs` 的 `status/placed`） |
| `FRAME_LIMIT` 的 12 列 × 8 排 × 8 层 | `utils/data.js` | **3 列 × 1 排 × 4 层**（与交付单一致） |

登录后温湿度、曲线、告警、设备控制已全部走后端（见第 12 节）；未登录（演示模式）才由本机模拟引擎产生。

### 12.1 两套基址与鉴权

| 用途 | 基址 | 鉴权 | 信封 |
| --- | --- | --- | --- |
| 环境调控（实时/历史/告警/控制/账号/令牌） | `http://10.66.66.1/api`（**已含 /api**，只走 WireGuard 隧道） | 真 JWT `Authorization: Bearer <access_token>` | 成功=裸对象；失败 `{error:{code,message,detail}}` |
| 病蚕识别 / 裁定 / 夹取作业 | `http://115.191.10.217:8000`（**不含 /api**，路径自带 `/api/*`，公网可达） | 只校验头存在（不验签） | `{ok,data,total}` / `{ok:false,error}` |

- 两者都是 **http**，Android 9+ 需放开明文：`uni-app/manifest.json` 的 `app-plus.distribute.android.usesCleartextTraffic: true`。
- 登录：`POST /auth/login {username,password}` → `{access_token,refresh_token,expires_in:7200,user:{user_id,username,role,display_name}}`；`GET /auth/me` → `capabilities[]`。
- **按钮权限按 `capabilities[]` 判断**（view/hist/ack/manual/config_change/token_issue/user_manage），不要硬编码 role；后端未返回 capabilities 时前端用 `ROLE_CAPS` 兜底。
- 401：先 `POST /auth/refresh {refresh_token}` 重试一次，仍失败才回登录页（`utils/http.js` 的 `onUnauthorized` 自动完成，并发合流）。
- 令牌相关错误是 **403**（invalid_token / token_used / token_expired），不是 400。

### 12.3 页面接线

- `pages/login`：账号密码 + 服务器地址；登录成功 `reLaunch` 到蚕房选择页。
- `pages/room-select`：冷启动闸门 `if (auth.needsLogin()) reLaunch(login)`（我的 → 账号 里的「启动要求登录」控制）。
- `pages/index` / `pages/history` / `pages/device-detail`：登录后曲线取 `live.series()`（真实 `/history`），未登录用本机模拟。
- `pages/alerts` / `pages/alarm-detail`：登录后确认告警走 `POST /alarms/{event_id}/confirm`。
- `pages/control`：登录后设备开关走 `POST /control/manual`（`target` 映射 heat01↔heater、mist01↔mist），退出手动走 `POST /control/manual/exit`；令牌由 `POST /control/tokens` 签发。
- `pages/users` / `pages/tokens`：管理员管操作员账户、签发/撤销审批令牌。
- `pages/machine`：病蚕裁定与夹取作业见第 11 节。
