## 0. 总览：两个后端，两套基址

| 服务 | 基址（App 默认值） | 覆盖范围 | 鉴权 |
|---|---|---|---|
| **环境调控 barn-api** | `http://10.66.66.1/api`（WireGuard 隧道内；公网可改 `http://115.191.10.217:8000/api`） | 登录/账号/令牌 + 实时温湿度、历史、告警、设备、手动控制、调度状态 | JWT：`Authorization: Bearer <access_token>`；**成功返回裸对象** |
| **ISH 检测/夹取** | `http://115.191.10.217:8000`（**不含 `/api`**，路径自带 `/api/*`） | 病蚕识别记录、人工裁定、夹取作业 | 只校验头存在：`Authorization: Bearer <任意非空>`（App 默认发 `test`） |

**响应信封（两个后端不一样，注意区分）**

环境调控 barn-api（ENV）：**成功直接返回裸对象/数组，失败固定 `{error:{code,message,detail}}`**

```json
{ "access_token": "…", "refresh_token": "…", "expires_in": 7200, "user": { … } }   // 成功：裸对象
{ "error": { "code": "invalid_credentials", "message": "…", "detail": "…" } }      // 失败：HTTP 4xx/5xx + error
```

ISH 检测/夹取：**统一 `{ok,data,total}` 信封**

```json
{ "ok": true,  "data": <对象或数组>, "total": 12 }
{ "ok": false, "error": { "code": "bad_decision", "message": "…" } }
```

**客户端统一行为**

- 超时：普通请求 12 s；`POST /control/manual` ≥15 s；`POST …/confirm` **35 s**。
- 重试：网络错误 / 超时 / **5xx** 重试 1 次；**4xx 一律不重试**；`POST` 类写入默认不重试（幂等接口例外，见 ISH）。
- 401：先 `POST /auth/refresh` 换 token 后**自动重试原请求一次**；刷新也失败 → 清会话并回登录页。
- 时间字段：**一律 UTC 毫秒整数**（服务器返回秒级时间戳时，`< 1e12` 会被当秒处理）。
- 轮询：环境数据 5 s；病蚕待裁定列表 20 s（均只在前台页面订阅时启动）。

## 1. 环境调控 barn-api（ENV）

### 1.1 鉴权与会话

| # | 方法与路径 | 请求 | App 读取的响应字段 |
|---|---|---|---|
| A1 | `POST /auth/login` | `{"username":"admin","password":"…"}`（不带 Authorization） | `data.access_token`、`data.refresh_token`、`data.expires_in`（**秒**）、`data.user{ id, username, display_name, role, capabilities[] }` |
| A2 | `POST /auth/refresh` | `{"refresh_token":"…"}` | 同 A1（至少 `access_token` + `expires_in`） |
| A3 | `GET /auth/me` | — | 同 A1 的 `data.user`（用于「刷新身份」） |
| A4 | `POST /auth/logout` | — | 任意；失败也本地清会话 |

`role` 取值必须落在 `admin / operator / viewer`（也接受 `administrator`、`管理员`、`操作员`，客户端会归一）。

- 登录失败错误码：`invalid_credentials`、`account_disabled`、`unauthorized`。
- `capabilities` 若下发，客户端**优先按它**判权限；不下发则按角色矩阵。

### 1.2 账号管理（管理员）

| # | 方法与路径 | 请求体 | 备注 |
|---|---|---|---|
| B1 | `GET /auth/users` | — | 数组，或 `{items:[…]}` / `{users:[…]}` |
| B2 | `POST /auth/users` | `{username, password, display_name, role}` | `user_exists` / `weak_password` |
| B3 | `PATCH /auth/users/{id}` | 局部字段，如 `{role}`、`{disabled:true}` | `user_not_found` |
| B4 | `POST /auth/users/{id}/password` | `{password:"…"}` | 重置密码 |

### 1.3 审批令牌（ACTION_TOKEN）

| # | 方法与路径 | 请求体 | App 读取 |
|---|---|---|---|
| C1 | `GET /control/tokens` | — | 数组，或 `{items:[…]}`；元素 `{id, token, target, action, status, expire_at, created_at, memo}` |
| C2 | `POST /control/tokens` | `{target, action, memo, ttl_min}` | `data`（同上结构） |
| C3 | `POST /control/tokens/{id}/revoke` | — | 任意 |

`target` 来自设备/机械清单：`heat01 / fan01 / fan02 / mist01 / ac01 / exh01 / feed01 / grab01 / pal01`。

### 1.4 环境数据（页面只读）

| D3 | `GET /devices/{barn}/{zone}` | — | 设备清单与开关态 |

## 2. ISH 病蚕 / 夹取（已按交付单 1:1 实现）

| # | 方法与路径 | 请求 | 说明 |
|---|---|---|---|
| F1 | `GET /api/barns/{barn}/diseased` | `?status=pending\|done\|all&limit=1..500&zone=zone01` | 待裁定列表（App 默认 `status=pending&limit=50`） |
| F2 | `POST /api/barns/{barn}/diseased/{trayId}/confirm` | `?zone=`；体 `{decision:"yes"\|"no", operator, note, at}`；头 `X-Idempotency-Key: clamp-<barn>-<trayId>-<ts>` | `yes` 会阻塞到阶段回执（最坏≈19 s，客户端 35 s）；`no` 仅本轮忽略 |
| F3 | `GET /api/barns/{barn}/clamp/jobs` | `?status=all\|running\|done&limit=1..500&zone=` | 夹取作业；**只有 `placed===true` 才算真放到位** |
| F4 | `GET /api/barns/{barn}/patrol/status` | — | 可选，只展示 |

F1 元素字段（App 用到）：`trayId`、`at`、`layer/row/col`、`display`、`conf`、`subHits`、`trayDiseaseCount`、`level`、`status`、`clampStatus`、`grade`、`canConfirm`、`causeText`、`env{}`、`images[]`、`jobId`、`decidedAt`、`decision`、`operator`。

- 坐标口径：**列 1–3 / 排 1 / 层 1–4**（App 侧 `FRAME_LIMIT` 已按此改）。
- 错误码：`bad_status`(400)、`bad_decision`(400)、`unauthorized`(401，不重试)、`tray_not_found`(404)、`already_decided`(409)、`pass_running`(409)、`service_unavailable`/`patrol_failed`(503)。
- 图片是绝对 URL（`http://115.191.10.217/images/...`），App 不再拼基址。

## 3. 需要后端确认的 6 件事（重要）

1. **`/auth/*`、`/control/tokens` 这几条路径是客户端按 REST 约定推断的**——交付单里只给了 ISH 的病蚕/夹取三接口，账号体系没有文档。如果后端路径不同，只需改 `utils/auth.js` 顶部 `ENDPOINTS`（一处），页面不用动。
2. **登录响应字段名**必须是 `access_token / refresh_token / expires_in / user`（OAuth2 风格）。若后端用 `token / data.user`，告诉我，我改归一化。
3. **`role` 是否由服务端决定**（而不是客户端选）；App 会 `data.setRole()` 把后端角色接进本机权限矩阵。
4. **`capabilities` 是否下发**：下发则以它为准（更灵活）；不下发则 App 按 `admin/operator/viewer` 内置矩阵。
5. **refresh 是否轮换 refresh_token**：App 每次刷新都会整体覆盖本地会话，轮换/不轮换都能用。
6. **成功响应是否裸对象**：客户端按「ENV 成功=裸对象、失败=`{error:{code,message}}`」解析（见上文信封说明）。如果后端统一包了 `{ok,data}`，请告我一声，改 `utils/http.js` 的 `unwrap()` 一处即可。

## 4. 联调自检（5 步）

1. 连上 WireGuard → `curl http://10.66.66.1/api/health` 应返回 `{"ok":true,"status":"ok"}` 或 200 空体（成功即裸对象，不要包 `{ok,data}`）。
2. App「我的 → 后端接口 → 测试连接」→ 应显示成功与耗时。
3. 用后端给的 admin 账号登录 → 应进入蚕房选择页，顶部能看到角色。
4. 切 3 号蚕房（离线）→ 看板顶部出现「离线自治」条；切回 1 号 → 消失。
5. 有 pending 病蚕时，机械页出现「长按放行」红条；长按 → 服务端下发夹取 → 「夹取作业」卡出现 `placed`。

**常见错误对照**：`TIMEOUT` → 隧道/端口不通；`ENVELOPE` → 返回体既不是裸对象也不是 `{error:{…}}`（ISH 侧：不是 `{ok,data}`）；`UNAUTHORIZED` → 401 且刷新失败；`forbidden` → 角色不足；`service_unavailable` → 后端内部错误（App 已自动重试 1 次）。
